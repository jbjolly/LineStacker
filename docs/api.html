API reference¶

LineStacker¶

Stacking positions (Coord, readCatalog(), makeCoords(), readCoords()), their conversion to pixels, random positions, and the package settings (verbose, casa_logfile). The stacking itself is in LineStacker.image (cubes) and LineStacker.OneD_Stacker (spectra); LineStacker.analysisTools tests stacks.

LineStacker.verbose = True¶

When True (default), LineStacker reports what it does, the files it writes (with their full path), what it reads, and progress bars. Set LineStacker.verbose = False to silence it; every function that prints also takes verbose=True/False to decide for one call. Warnings about possible problems are shown either way.

LineStacker.casa_logfile = 'auto'¶

Where CASA writes its log when LineStacker starts CASA itself (only to read or write CASA images; FITS cubes never start CASA):

  • 'auto' (default): one file, <temporary dir>/linestacker-casa-<user>.log, instead of a new casa-<date>.log in the working directory at every run; a logfile set in ~/.casa/config.py is used instead.

  • a path: CASA’s log goes there.

  • None: no log file.

  • 'casa': CASA’s own default (casa-<date>.log in the working directory).

Set it before the first CASA image is read. Inside a CASA session, or once casatools/casatasks were imported, CASA’s own settings apply.

LineStacker.cache_check = True¶

Cubes are read once and kept in memory. When True (default) LineStacker checks, every time it uses a cached cube, that its file has not changed (about 0.1 ms per CASA image, a few microseconds per FITS file) and reads it again if it has. Set LineStacker.cache_check = False to trust the cache until LineStacker.image.clear_cache().

LineStacker.round_half_up(x)[source]¶

Round like Python 2’s round() did (halves away from zero). Python 3’s round() rounds halves to even, which would move some stack centres by one channel compared with LineStacker < 2.0.

class LineStacker.Coord(ra, dec, spec='continuum', weight=1, image=0, type='physical', imagenumber=-1, frame='icrs', z=None, index=None)[source]¶

Describes a stacking position on an image.

Class used internally to represent coordinates. May describe a physical coordinate or a pixel coordinate.

Init: Creates a coordinate. A pixel coordinate should always specify to which image it belongs. Physical coordinates are astropy angles (as produced by LineStacker.readCoords, readCatalog and makeCoords) or plain numbers in radians, in the equatorial frame given by frame (default ICRS).

Parameters:

  • ra – x coordinate of stacking target (RA, or x pixel for pixel coordinates). Also available as coord.x.

  • dec – y coordinate of stacking target (Dec, or y pixel). Also coord.y.

  • spec – spectral coordinate of stacking target (redshift, observed spectral value or channel depending on spectralMethod). Also coord.z.

  • weight – Weight of the source for mean stacking. Default is 1.

  • image – Cube associated to the source, either its path or its index in the list of images given to the stacking function. Automatically set with LineStacker.readCoords.

  • type – Either ‘physical’ or ‘pixel’

  • imagenumber – Index of the cube in the image list (set by readCoords to the index of the coordinate file the source was read from).

  • frame – Equatorial frame of ra, dec: ‘icrs’ (default), ‘fk5’ (J2000), ‘fk4’…

LineStacker.readCoords(coordfiles, unit='deg', lineON=True, delimiter='default', frame='icrs', images='default', type='physical', verbose=None)[source]¶

Reads coordinate files (one file per cube, the format of LineStacker 1.x) and returns a list of LineStacker.Coord.

Parameters:

  • coordfiles – List of path to coordinate files. Files in csv format. x and y should be in J2000. If using to stack line, redshift should be in the third column. A weight may be added in the last column to weight positions for mean stacking. If set to None stacking position is defined as the center of each cube. Coordinates can either be in degrees (e.g. “10.625, 41.2”), or in hour angle + deg, as hms dms format (e.g. “‘00h42m30s’, ‘+41d12m00s’”), or as hour angle + deg without hms nor dms (e.g. “00 42 30, +41 12 00” or CASA’s “00:42:30, +41.12.00”). Empty lines and lines starting with # are ignored.

  • unit – Unit of input coordinates. Allows two values, ‘deg’ or ‘rad’.

  • lineON – Either True or False, should be set to True if doing line stacking. Default is True.

  • delimiter – Delimiter used to separate coordinates, ‘default’ tries comma, space and tab (in that order).

  • images – List of images to which each coordfile is assigned, if set to ‘default’, image names are same as coordfiles, with ‘.fits’ instead of ‘_coord.txt’. The stacking functions also accept coordinates whose image is not in their imagenames list: the n-th coordinate file is then matched to the n-th image.

  • type – Coordinate type, can be either ‘physical’ (default), or ‘pixel’

  • verbose – report how many positions were read (default: LineStacker.verbose)

Builds stacking coordinates directly from Python values (lists, numpy arrays, astropy quantities or a SkyCoord), e.g. in a notebook.

Parameters:

  • ra – Positions, one value per source. Numbers are in unit (or pixels if type=’pixel’); astropy Angles/Quantities carry their own unit; strings are sexagesimal with RA in hours (‘03:31:04.15’, ‘-27:40:59.87’, or CASA’s ‘-027.40.59.866’). A SkyCoord can be given as ra, with dec=None.

  • dec – Positions, one value per source. Numbers are in unit (or pixels if type=’pixel’); astropy Angles/Quantities carry their own unit; strings are sexagesimal with RA in hours (‘03:31:04.15’, ‘-27:40:59.87’, or CASA’s ‘-027.40.59.866’). A SkyCoord can be given as ra, with dec=None.

  • z – Spectral value of each source: the redshift for spectralMethod=’z’ (the default of LineStacker.image.stack), the observed frequency/wavelength for ‘obsSpec’, the channel for ‘channel’. None for continuum stacking.

  • weight – Weight of each source for mean stacks (default 1).

  • image – Cube of each source (path to a FITS file or CASA image), or one path for all sources. None when all sources lie in the single cube given to the stacking function.

  • unit – ‘deg’ (default) or ‘rad’, for plain numbers.

  • frame – Equatorial frame of the positions: ‘icrs’ (default), ‘fk5’ (J2000), ‘fk4’… A SkyCoord in any frame (e.g. Galactic) is converted to it.

  • type – ‘physical’ (sky positions, default) or ‘pixel’.

LineStacker.readCatalog(catalog, ra='ra', dec='dec', z='z', weight='weight', image='image', unit='deg', frame='icrs', imagedir=None, format=None, verbose=None)[source]¶

Reads the stacking positions of all sources from one catalogue table, one row per source. The cube of each source is given in the table (image column); it is never guessed.

Parameters:

  • catalog – Path to a table file: CSV (with a header line), ECSV, FITS table, VOTable or any format astropy.table reads (see format). Also accepted: an astropy Table, a pandas DataFrame or a dict of columns.

  • ra – Column names of the positions (default ‘ra’, ‘dec’; also found: RAJ2000/DEJ2000, ra_deg/dec_deg…). Numbers are in unit unless the column has a unit (FITS, ECSV, VOTable); strings are sexagesimal with RA in hours (CASA’s ‘-027.40.59.866’ accepted).

  • dec – Column names of the positions (default ‘ra’, ‘dec’; also found: RAJ2000/DEJ2000, ra_deg/dec_deg…). Numbers are in unit unless the column has a unit (FITS, ECSV, VOTable); strings are sexagesimal with RA in hours (CASA’s ‘-027.40.59.866’ accepted).

  • z – Column of the spectral value (default ‘z’, also ‘redshift’): the redshift, or the observed frequency/wavelength or channel for spectralMethod ‘obsSpec’/’channel’. If the catalogue has no such column (or z=None) the positions are for continuum stacking.

  • weight – Column of the weights (optional, default 1).

  • image – Column naming the cube of each source (FITS file or CASA image; default ‘image’, also ‘cube’, ‘file’). Relative paths are looked up next to the catalogue first, then from the working directory. Without this column, give the stacking function a single cube.

  • unit – ‘deg’ (default) or ‘rad’, for unit-less numeric positions.

  • imagedir – Folder to which relative cube names are relative (overrides the rule above).

  • format – astropy table format, e.g. ‘ascii.csv’, ‘ascii.commented_header’ (default: guessed from the file).

  • verbose – report what was read (default: LineStacker.verbose)

Returns:

list of LineStacker.Coord – for LineStacker.image.stack and the analysis tools; imagenames can be omitted there when the catalogue has an image column.

LineStacker.image¶

Stacking in the image domain: spectral lines in data cubes, or continuum.

Inputs are FITS files or CASA images (CASA images need casatools), and can be mixed. Line stacking extracts a sub-cube around each source, centred on its line; continuum stacking (continuum=True) stacks images. Cubes without a spectral axis (or with a single channel) are always stacked as continuum; cubes with a spectral axis are collapsed in memory when continuum stacking is asked for (with a warning).

What the stacked cube is:

  • Stamps are cut on each cube’s own pixel grid, centred on the source; cubes are not reprojected. Cubes whose pixels differ in size or orientation, or whose projection, celestial frame or distortions differ, from the first cube’s give a warning: reproject them first (e.g. CASA imregrid) to use the stacked image spatially.

  • The output sky axes are offsets from the stacked position, (0, 0) at the stamp centre, with the first cube’s pixel size and orientation.

  • All cubes must have the same kind of spectral axis (FREQ, WAVE, AWAV, VRAD…); units are converted to those of the first cube, in which fEm, lEm and observed spectral values are given. Non-linear spectral axes are refused for line stacks. Different spectral reference frames (SPECSYS) give a warning: LineStacker does not convert frames.

  • The beam in the header (BMAJ, BMIN, BPA) is the mean of the input beams, an approximation of the stack’s effective beam when they differ.

  • Blank pixels (NaN) stay NaN and are left out pixel by pixel; stacked pixels without any valid data are NaN.

  • Pixel units (BUNIT) are compared: scaled units are converted to the first cube’s (mJy/beam to Jy/beam), recognised but physically different ones are refused, unrecognised ones give a warning.

  • A continuum stack of collapsed cubes keeps BUNIT, which is then per channel (‘sum’ adds channels); the COLLAPSE keyword says how.

LineStacker.image.stack(coords, outfile='stackResult.fits', stampsize=32, imagenames=None, method='mean', spectralMethod='z', weighting=None, returnWeights=False, maskradius=0, fEm=-1, lEm=-1, N_chans='default', plotIt=False, regridFromZ=False, regridMethod='scaleToMax', saveSubCubes=False, hdul='auto', continuum=False, collapse='sum', primarybeam=None, verbose=None)[source]¶

Performs line (or continuum) stacking in the image domain.

Parameters:

  • coords – A list of LineStacker.Coord (see LineStacker.readCatalog, LineStacker.makeCoords, LineStacker.readCoords). Set to None to stack the centre of every cube.

  • outfile – Target name for stacked image. Names ending in .fits are written as FITS, other names (e.g. ‘stackResult.image’) as CASA images (needs casatools). None to skip writing.

  • stampsize – size of target image in pixels

  • imagenames – Cubes or images to extract flux from: FITS files or CASA images (both can be mixed), in the same order as the coordinate files. Can be omitted when every coordinate names its cube (readCatalog with an image column, makeCoords(image=…)). All cubes must have the same kind of spectral axis (e.g. all FREQ); different units (Hz, GHz) are converted to those of the first cube. Stamps are cut on each cube’s own pixel grid: cubes with other pixel sizes or orientations are not reprojected (a warning says so).

  • method – ‘mean’ (weighted) or ‘median’ (over the sources covering each channel; weights are ignored)

  • spectralMethod –

    What the spectral value of each coordinate (its z, the 3rd column of a coordinate file) is. Possible methods are:

    ’z’: the redshift of the observed line, if used fEm (emission frequency) or lEm (emission wavelength) must be informed as an argument of this Stack function.

    ’obsSpec’: the (observed) central frequency, wavelength or velocity, in the spectral unit of the first cube.

    ’channel’: the channel number (0-based) of the line.

  • weighting –

    used if method set to ‘mean’, possible values are:

    ’sigma2’: weight times 1/sigma**2, sigma being the standard deviation of the source’s stamp (pixels outside maskradius, blank pixels excluded)

    ’sigma2F’: the same, computed channel by channel

    ’1/A’, /!\ only use if lines are visible pre-stacking: weight divided by the line amplitude (maximum of the central-pixel spectrum; sources with a non-positive amplitude get weight 0)

    ’sigma’: weight times 1/sigma (sigma as for ‘sigma2’; if maskradius is 0 the mask radius is twice the beam major axis)

    ’pb’: weight times the squared primary-beam response at each source (needs primarybeam); for primary-beam corrected images this is inverse-variance weighting

    None: the weights of the coordinates (1 by default).

    Each weighting multiplies the coordinates’ own weights. Weights must be finite and >= 0.

  • returnWeights –

    If true weights of each source are written in outfile “weightFile.csv” in format: coord.ra, coord.dec, coord.z, coord.weight.

    If multiple weights exist for one source (for each spectral channel) all are written.

  • maskradius – allows blanking of centre pixels in weight calculation

  • fEm – rest emission frequency of the line, should be used if spectralMethod = ‘z’ and spectral axis of image cube is in frequency (in the unit of the first cube, usually Hz).

  • lEm – rest emission wavelength of the line, should be used if spectralMethod = ‘z’ and spectral axis of image cube is in wavelength (in the unit of the first cube, e.g. Angstrom for MUSE).

  • N_chans – number of channels of the resulting stack, default is number of channels in the first image.

  • plotIt – direct plot option

  • regridFromZ – if set to True each source’s spectrum is resampled (linear interpolation) so that all sources share the same rest-frame channel width, correcting the redshift dependence of observed line widths. Requires spectralMethod=’z’.

  • regridMethod – Used if regridFromZ is True. Can be set either to ‘scaleToMin’ or ‘scaleToMax’. The common rest-frame channel is the one of the source with the smallest (‘scaleToMin’) or highest (‘scaleToMax’) redshift.

  • saveSubCubes – If set to True (or to str) sub cubes will be saved as a numpy file. (outSubCubes.npy if set to True, user defined is set to str)

  • hdul – index of the FITS HDU holding the cube; ‘auto’ (default) picks the first HDU containing an image.

  • continuum – If True, stack continuum images instead of lines (spectralMethod, fEm, lEm, N_chans and regridFromZ are then not used). Continuum stacking is also used automatically when no image has a spectral axis (or only one channel), and when the coordinates carry no spectral value (readCoords(…, lineON=False)). Cubes with a spectral axis are then collapsed in memory (with a warning), see collapse.

  • collapse – How cubes are collapsed for continuum stacking: ‘sum’ (default), ‘mean’ or ‘median’ over channels. Blanked channels are ignored.

  • primarybeam – Used by weighting=’pb’: the primary-beam image of each cube (FITS or CASA, e.g. tclean’s .pb), as one path for a single cube, a list in the order of imagenames or a dict {cube: pb image}; the response is read at each source’s position (and line channel). Or a function f(dx, dy, nu) returning the response at offsets dx, dy (radians, east and north on the sky) from the image reference pixel and frequency nu (Hz, None without a frequency axis), e.g. GaussianPrimaryBeam(dish=12.). Entries of a list or dict can also be functions.

  • verbose – If True, print the path of every file written (stacked cube, weights, sub-cubes). Default: LineStacker.verbose (True unless changed).

Returns:

list – [central pixel at the central channel, spectrum of the central pixel, stacked cube (x, y, stokes, channel), number of sources missing from each channel]. For a continuum stack the spectrum has one channel.

LineStacker.OneD_Stacker¶

Stacking of 1D spectra: each spectrum is a Spectrum, which knows where its line is; Stack() aligns the spectra on their lines and averages them channel by channel. Velocities are in km/s.

class LineStacker.OneD_Stacker.Spectrum(spectrum=None, amp=None, velocities=None, frequencies=None, z=None, fEmLine=False, centerIndex=None, centralVelocity=None, centralFrequency=None, weights=1, name='', fit=False, velOrFreq='vel', velConvention='radio')[source]¶

One spectrum to stack: its fluxes, optionally its spectral values, and where its line is.

Parameters:

  • spectrum – Spectrum should be of the shape [N,2] or [2,N], where N is the number of spectral bins. The second dimension being the flux and the first the spectral values, which must be evenly spaced (increasing or decreasing; within 5% of a channel).

  • amp – Instead of defining spectrum one can define only the amplitude (flux).

  • velocities – In the case where amp is defined it is still possible to define the velocities

  • frequencies – In the case where amp is defined it is still possible to define the frequencies

  • z – Redshift, one of the possible way to define central frequency. If using redshift fEmLine (emission frequency of the line) should be defined. In addition the spectrum should consist of BOTH amplitudes and spectral information (frequencies or velocities), and not amplitude alone. Velocities are then in km/s relative to the rest frequency fEmLine (as e.g. a CASA spectrum with restfreq=fEmLine), in the convention velConvention: the line is at v = c z/(1+z) (radio), c z (optical) or c((1+z)**2-1)/((1+z)**2+1) (relativistic).

  • fEmLine – Emission frequency of the line, needed if redshift argument is used.

  • centerIndex – channel index of the line center, another possible way to define line center.

  • centralFrequency – (observed) Frequency of the line center, another possible way to define line center.

  • centralVelocity – Observed velocity of the line center, another possible way to define line center.

  • weights –

    The weighting scheme to use.

    Can be set to ‘1/A’ or ‘sigma2’. If sigma2 is used std of the entire spectra is used UNLESS, fit is set to True, in which case the central part around the line is excluded from std calculation (central here means one FWHM on each side of the center of the line).

    Alternatively user input can be used, float or list (or array)

  • name – name of the spectrum, can allow easier identification

  • fit – If fit is set to True, the spectrum will be fitted with a gaussian to try and identify the line center (as well as amplitude if weight is set to 1/A)

  • velOrFreq – Defining if spectral dimension is velocity or frequency.

  • velConvention – Velocity convention of the velocities (km/s), used with z: ‘radio’ (default, as CASA and LineStacker.uv), ‘optical’ or ‘relativistic’.

LineStacker.OneD_Stacker.Stack(spectra, chansStack='full', method='mean', center='lineCenterIndex', regridFromZ=False, regridMethod='scaleToMin', verbose=None)[source]¶

Stacks spectra (LineStacker.OneD_Stacker.Spectrum objects), aligned on their lines: weighted mean or median, channel by channel.

Parameters:

  • spectra – List of spectra (LineStacker.OneD_Stacker.Spectrum objects).

  • chansStack – Number of channels to stack. Set to ‘full’ to stack all channels from all spectra. User input (int) otherwise

  • method – stacking method, ‘mean’ and ‘median’ supported

  • center –

    Method to find central frequency of the stack, possible values are:

    ”center”, to stack all spectra center to center,

    ’fit’ to use gaussian fitting on the spectrum to determine line center,

    ’zero_vel’ to stack on velocity=0 bin,

    ’lineCenterIndex’ use the line center initiated with the spectrum,

    Or directly defined by the user (int)

  • regridFromZ – if set to True spectra will be regridded to take into account the redshift difference of the different sources. See LineStacker.analysisTools.regridFromZ1D for a more complete description.

  • regridMethod – Used if regridFromZ is True. Can be set either to ‘scaleToMin’ or ‘scaleToMax’. In the first case all spectra are regridded to match the smallest redshift (over-gridding), all spectra are regridded to match the highest redshift in the other case (under-gridding).

  • verbose – report the regridding (default: LineStacker.verbose)

Returns:

tuple – (stacked spectrum, number of spectra in each channel). Channels without valid data (no spectrum covers them, or only blank fluxes or zero weights) are NaN.

LineStacker.analysisTools¶

Tools to test stacks and prepare data for stacking: bootstrapping, subsampling, stacks at random positions, noise estimates, rebinning and regridding of lines of different widths and redshifts.

The Monte-Carlo tools (bootstraping_OneD, bootStraping_Cube, subsample_OneD, stack_estimator) accept n_jobs (number of CPU cores, -1 for all), backend (‘process’ or ‘thread’, see LineStacker.tools.parallel), seed and verbose. All random draws happen before the work is split, so results do not depend on n_jobs. With seed=None the draws come from numpy’s global random state, so np.random.seed() still makes runs reproducible.

LineStacker.analysisTools.bootstraping_OneD(spectra, nRandom=1000, chansStack='full', method='mean', center='lineCenterIndex', save='all', seed=None, n_jobs=1, backend=None, verbose=None)[source]¶

Bootstrapping of a 1D stack: stacks of random draws, with replacement, of the spectra. See LineStacker.OneD_Stacker.Stack for the stacking parameters.

Parameters:

  • spectra – a list of LineStacker.OneD_Stacker.Spectrum objects

  • nRandom – number of bootstrap iterations

  • chansStack – number of channels to stack, either a fixed number or ‘full’ for entire spectra

  • method – stacking method, ‘mean’ or ‘median’

  • center – Method to center spectra. See LineStacker.OneD_Stacker.Stack for further information on centering methods.

  • save –

    data to save at each bootstrap iterations

    possible values are ‘all’, ‘amp’ and ‘ampAndWidth’

    ’all’ saves the full stack at each bootstrap iteration (can use a lot of memory)

    ’amp’ saves the amplitude of the line (maximum value of the stack) at each bootstrap iteration, fastest

    ’ampAndWidth’ fits the line with a gaussian and saves the corresponding amplitude and width at each bootstrap iteration (fits that do not converge are stored as [nan, nan]), can be cpu expensive.

  • seed – seed for reproducible resampling (None uses numpy’s global random state)

  • n_jobs – number of CPU cores to use (-1 for all). Worth it mostly for ‘ampAndWidth’ and for medians.

  • backend – ‘process’ or ‘thread’, see LineStacker.tools.parallel

  • verbose – print what is done and a progress bar (default: LineStacker.verbose)

Returns:

list – nRandom+1 entries (as chosen by save), the first one for the stack of all spectra.

Cube regridding function correcting the observed linewidth change due to redshift. LineStacker.tools.parallel¶

Small helper to spread Monte-Carlo iterations (bootstraps, subsamples, random stacks) over several CPU cores.

Every function in LineStacker that accepts n_jobs draws all its random numbers up front, in the calling process, and only distributes the deterministic work. Results are therefore identical whatever n_jobs or backend is, and reproducible with seed.

backend='process' (default) runs workers in separate processes and is the right choice for Python-heavy work such as Gaussian fits. backend='thread' avoids starting processes and copying data; it helps when the work is mostly large numpy operations (e.g. median stacks of big cubes).

When using processes from a script on macOS or Windows, protect the script’s entry point:

if __name__ == '__main__':
    main()

otherwise each worker re-runs the script while starting.
